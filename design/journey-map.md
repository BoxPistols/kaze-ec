# カスタマージャーニーマップ — どこが繋がっていて、どこが切れているか

[`personas.md`](personas.md) の人物が実際にどう動くか。
**現状の実装で通れる区間と、切れている区間を同じ表に並べる。**

> 「理想の体験」を描いた図は、実装と照合できないので使わない。
> ここでは各段階に **実装状況** の列を持たせ、次に作るものが表から導かれるようにする。

凡例: ✅ 実装済み / 🚧 部分的 / ❌ 未実装

---

## 1. 購入ジャーニー（佐藤・田中 共通）

| # | 段階 | 行動 | 感情・迷い | 必要なもの | 状況 |
| - | ---- | ---- | ---------- | ---------- | ---- |
| 1 | 探索 | 一覧を眺める / 検索する | 「欲しいものがあるか」 | 検索・カテゴリ・タグ絞り込み・並び替え | ✅ |
| 2 | 比較 | 複数の候補を見比べる | 「状態と価格が見合うか」 | 価格・状態バッジ・写真枚数の一覧表示 | ✅ |
| 3 | 検討 | 商品詳細を読む | 「傷はどこか」「出品者は信用できるか」 | 複数写真・説明・出品者情報・関連商品 | ✅ |
| 4 | 保留 | いいねして後で考える | 「まだ迷う」 | お気に入り（ハート） | 🚧 保存されない |
| 5 | 決済 | 支払い方法を選ぶ | 「円で払うか暗号資産か」 | 原資トグル・手数料内訳 | ✅ |
| 6 | 待機 | 発送を待つ | 「ちゃんと届くか」 | エスクロー状態の可視化 | ✅ |
| 7 | 完了 | 受取・評価 | 「また買うか」 | 取引完了表示 | 🚧 評価が無い |
| 8 | 振り返り | 購入履歴を見る | 「あれいつ買ったか」 | **購入履歴** | ✅ `/mypage` |

### 切れている区間

- **4（保留）**: ハートは押せるが再読み込みで消える。「後で考える」が成立していない
- **7（完了）**: 評価が無い

---

## 2. 出品ジャーニー（佐藤）

| # | 段階 | 行動 | 感情・迷い | 必要なもの | 状況 |
| - | ---- | ---- | ---------- | ---------- | ---- |
| 1 | 動機 | 「これ売れるかな」と思う | 買い物中・片付け中に思いつく | **どこからでも出品に入れる導線** | ✅ ヘッダーの出品ボタン |
| 2 | 相場観 | 似た商品の価格を見る | 「いくらで出すか」 | 同カテゴリの価格帯 | 🚧 一覧で見られるが出品時に見られない |
| 3 | 出品 | 写真・説明・価格を入力 | **「面倒くさい」** | **出品フォーム** | ✅ `/sell` |
| 4 | 公開 | 出品完了 | 「反応あるかな」 | 完了確認 | ✅ 完了画面 → 出品管理 |
| 5 | 観察 | 反応を見る | 「いいねは付いたが売れない」 | **出品管理（一覧・ステータス）** | ✅ `/mypage?tab=listings` |
| 6 | 施策 | 値下げする / 説明を直す | **「値下げすべきか分からない」** | **反応の推移・判断材料** | ❌ |
| 7 | 成約 | 売れた | 「発送しなきゃ」 | 通知・発送手続き | ❌ |
| 8 | 振り返り | 売上を見る | 「今月いくら売れたか」 | 売上サマリ | ❌ |

### 切れている区間

1〜5 が繋がり、**出品して、公開して、反応を見返せる**ところまで通った。

残るのは 6〜8。6（値下げ判断）は分析の領域で、モックデータでは意味のある
数字が出ないため別スコープに切っている（[`decisions/0003`](decisions/0003-analytics-scope.md)）。
2（相場観）は出品時に同カテゴリの価格帯が見られないため 🚧 のまま。

## 3. 役割の往復（C2C 固有）

主ペルソナは購入と出品を行き来する。**その接続点が設計上いちばん重要。**

```
購入ジャーニー 7（完了）───┐
                          ├──→ 出品ジャーニー 1（動機）
探索中に「これ売れるかな」──┘
```

観測できる事実として、出品を思い立つ場面は 2 つある。

| 思い立つ場面 | 必要な導線 | 状況 |
| ------------ | ---------- | ---- |
| 買い物をしている最中（相場を見て） | どの画面からも出品へ | ✅ ヘッダーの出品ボタン |
| 取引が終わった直後（片付けの流れ） | 取引完了画面から出品へ | ❌ 決済完了画面に導線が無い |

**役割を持ち替える場所が「マイページ」**。購入履歴と出品管理を 1 画面に並べ、
切り替えをタブで行う（→ [`decisions/0002`](decisions/0002-role-switching.md)）。
タブの状態は URL に持つので、出品管理を人に共有できる。

出品を**始める**導線はヘッダーに常設した。出品後は完了画面から出品管理へ
戻すので、`/sell` → `/mypage?tab=listings` で往復が閉じる。

## 4. 表から導かれる優先順位

**感想ではなく、切れている区間の数と依存関係から決める。**

**済**: マイページ（購入 8 / 出品 5）→ 出品フォーム（出品 3）→ 出品完了導線（出品 4・1）

| 優先 | 作るもの | 根拠 |
| ---- | -------- | ---- |
| 1 | 取引完了 → 出品への導線 | 役割往復の残り半分。決済完了画面に 1 本足すだけ |
| 2 | 出品時に同カテゴリの価格帯を出す | 出品 2。「いくらで出すか」に直接効く |
| 3 | お気に入りの永続化 | 購入 4。単独で価値が小さい |
| 4 | 評価 | 購入 7。相手が要るので設計判断が別途必要 |
| 5 | 反応の推移・値下げ判断 | 出品 6。**データ設計が別途必要**（分析の話になる） |

**5 は分析の領域**で、モックデータでは意味のある数字が出ない。
別スコープとして切る（→ 分析の設計は [`decisions/0003`](decisions/0003-analytics-scope.md)）。

## 5. この表の使い方

- **画面を作る前**: 該当する段階の行を読み、「何に困っているか」を確認する
- **画面を作った後**: 状況の列を更新する。**🚧 のまま放置しない**
- **新しい機能を思いついたとき**: この表のどの段階を埋めるかを言えなければ作らない
