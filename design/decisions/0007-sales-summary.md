# 0007. 売上サマリで、何を出して何を出さないか

日付: 2026-08-27
状態: 決定
ジャーニー: 出品 8（振り返り・「今月いくら売れたか」）

## 問題

出品ジャーニー 8 が ❌ のまま残っていた。「売上サマリ」を作ろうとして、
**売却の記録が 1 件も無い**ことが分かった。

既存のデータはこうなっている。

| データ | 中身 | 誰の視点 |
| ------ | ---- | -------- |
| `LISTINGS` | カタログ 8 件（うち自分の出品は 2 件） | 全体 |
| `PURCHASES` | 3 件 | **自分が買った**もの |

`PURCHASES` は購入者としての記録で、**売った記録ではない**。
自分の出品 2 件（`l-001` / `l-003`）はどちらも公開中で、売れていない。

### 併せて見つかった不具合

`selectMyListings` は売却済みを次の条件で判定していた。

```
自分の出品 ID が、PURCHASES（自分が買ったもの）の listingId 集合に含まれるか
```

**自分が自分の出品を買わない限り true にならない。** 構造上成立しない条件で、
マイページの「売却済み 0」は常に 0 だった。

問題は 0 が**正しく見える**こと。売れていないのか、数えられていないのかが
画面から区別できない。値が壊れていれば気づくが、0 は気づけない。

## 決定

### 1. 売却記録を別ソースとして持つ

`SALES` を追加する。`PURCHASES`（自分が買った）とは別。
売却済みの判定は `SALES` から引く。

**同じ配列で両方を兼ねない。** 兼ねると、上の不具合と同じ形が必ず戻る。
購入と売却は当事者が逆なので、同じ形をしていても別の事実。

### 2. 合計を 1 つの数字で出さない

**確定した売上と、確定していない売上を分ける。**

| 状態 | 売上として | 理由 |
| ---- | ---------- | ---- |
| 取引完了 | **確定** | 受け取りまで終わっている |
| 発送済み | 未確定 | 受取確認前。返品・不着がありうる |
| 発送待ち | 未確定 | まだ発送していない |

決済画面が「発送確認まで保留」とエスクローを見せている
（[`0001`](0001-wallet-hybrid-settlement.md)）のに、売上側で全部足して
1 つの数字にすると、画面ごとに言っていることが変わる。

### 3. 手数料は売上から引かない

現行の決済は**購入者が手数料を負担する**（`CheckoutWalletPage` の
`total = price + fee`）。出品者の受取額は販売価格そのもの。

一般的なフリマは出品者から手数料を取るが、**そちらに変えるなら決済画面の
設計判断をやり直す必要がある**ので、ここでは変えない。代わりに
「手数料は購入者負担」と画面に明記する。書かないと、受取額が
販売価格と同じことの理由が読み取れない。

### 4. 決済原資の内訳は出す

円決済とステーブルコイン決済の件数を分けて出す。手数料率が違う
（5% / 2%）ので、**購入者から見た支払総額は原資で変わる**。
出品者にとっては受取額が同じでも、どちらで買われたかは
値付けの判断材料になる。

**為替差や換算レートは出さない。** ステーブルコイン建ての受取額を
円換算する仕組みを持っていないので、出せば作り話になる。

### 5. 平均単価・成約率は出さない

売却 3 件から平均を出しても、その 3 件の値そのものにしかならない。
[`0005`](0005-price-reference.md) で相場を出さないと決めたのと同じ理由。

成約率（売れた数 ÷ 出品数）も出さない。出品数が 2 件しかなく、
分母が動くたびに大きく振れる。

## 出さないものの一覧（画面にも書く）

- 平均単価・中央値
- 成約率
- 前月比・伸び率
- 「あと N 円で目標達成」のような予測

いずれも**件数が足りない**か、**そのデータを持っていない**。

## 影響

- `src/data/account.ts` に `SALES` と集計の純関数を足す
- `selectMyListings` の売却判定を `SALES` に切り替える（不具合の修正）
- マイページの出品タブに売上サマリを置く。新しい画面は作らない
  （[`0002`](0002-role-switching.md) でマイページを役割の持ち替え場所に
  決めているので、振り返りもそこに置く）

## 却下した案

**新しい `/sales` 画面を作る** — 役割の持ち替えがマイページに集約されて
いるのに、出品側の振り返りだけ別画面にすると導線が二重になる。
購入 8（購入履歴）がマイページにあるのと揃えた。

**合計だけ大きく出す** — 一番読まれる数字を、確定していないものを
含めて出すことになる。エスクローを見せている決済画面と矛盾する。
