# 0001: 決済方法は「円 / ステーブルコイン」をトグルで並列表示する

- 状態: 決定
- 対象画面: `CheckoutWalletPage`

## 問題

C2C フリマの決済に暗号資産（ステーブルコイン想定）を足すとき、UI 側の選択肢は主に 2 つある。

1. 決済方法選択画面に「暗号資産」を 1 項目として追加する（銀行振込・カードと横並び）
2. 円残高とステーブルコイン残高を同じウォレットの中の 2 通貨として扱い、
   その場でトグル切り替えできるようにする

## 決定

2 を採る。`CheckoutWalletPage` では単一のウォレットカードの中に円残高と
ステーブルコイン残高を両方表示し、`ToggleButton`（kaze の `ToggleButton` 仕様、
`exclusive` 制御）で支払い原資を切り替える。決済方法の選択画面を別途は作らない。

## 理由

- フリマの決済は「持っている残高で払う」体験に近い。暗号資産を独立した
  決済手段として並べると、ウォレット的な文脈が失われ、単なる決済プロバイダの
  追加に見えてしまう
- 円とステーブルコインを**同じ画面の同じ粒度**で見せることで、「暗号資産だけ
  特別な手続きが要る」という心理的な壁を作らない
- 手数料はどちらの原資でも表示位置を固定する（通貨で UI 構造を変えない）。
  切り替えても「同じ決済フローの中にいる」という一貫性を優先した

## トレードオフとして受け入れたこと

- ステーブルコイン残高が 0 の利用者には、切り替え自体が意味を持たない。
  この画面では残高 0 のときトグルを disabled にし、「チャージ」導線を出す
  （実装は `CheckoutWalletPage` 内、モックデータのみ）
- 発送確認前の資金は決済完了ではなく保留状態として見せる（エスクロー的な
  安全設計）。円・ステーブルコインどちらの原資でも保留状態の見え方は統一する

## スコープ外

- 実際のオンチェーン処理・KYC・レート変動の反映（本リポジトリは UI/UX の
  実演が目的で、モックデータのみを扱う）
