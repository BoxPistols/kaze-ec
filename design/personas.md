# ペルソナ — 誰のために作るか

kaze-ec の画面設計の前提。**AI に画面を作らせるときの入力**でもあるので、
「共感を得るための人物像」ではなく**判断に使える形**で書く。

> ペルソナは飾りではない。「この画面に何を出すか」で迷ったとき、
> 戻ってくる場所として置く。迷いを解けない記述は書かない。

---

## 0. C2C の前提 — 役割は属性ではなく状態

**同一人物が購入者にも出品者にもなる。** これが C2C の定義そのもので、
BtoC との最大の違い。

```
BtoC:  買う人 ─────────→ 売る事業者      役割は固定（属性）
C2C:   人 ⇄ 役割を行き来する               役割は可変（状態）
```

設計上の帰結:

- **「購入者向けアプリ」と「出品者向けアプリ」に分けない。** 分けると、
  役割を行き来するたびにログインし直すような体験になる
- **役割の切り替えコストを最小にする。** 出品を思い立つのは、たいてい
  「買い物をしている最中」か「取引が終わった直後」
- **同じ人の 2 つの顔を 1 画面に同居させる**（→ [`0002`](decisions/0002-role-switching.md)）

## 1. 主ペルソナ — 佐藤 みなみ（両役割・往復型）

**このプロダクトの中心。** 全画面がこの人を基準に設計されている。

| 項目 | 内容 |
| ---- | ---- |
| 属性 | 30 代 / 会社員 / 都市部在住 / スマホ中心（PC は月数回） |
| 利用歴 | フリマアプリ歴 4 年。購入が先、出品は 2 年目から |
| 頻度 | 購入 月 2〜3 回 / 出品 月 1〜2 回（不定期にまとめて出す） |
| 出品規模 | 常時 3〜8 件。売れ残りを抱えている自覚がある |

### 何をしたいか

- **買う側**: 欲しいものを、状態と価格が納得できる形で見つけたい
- **売る側**: 使わないものを、**手間をかけずに**、妥当な値段で手放したい

### 何に困っているか（判断に効くもの）

| 困りごと | 設計への帰結 |
| -------- | ------------ |
| 出品したが売れない。値下げすべきか分からない | 出品管理に「反応の推移」が要る。値下げ判断の材料 |
| 自分の出品と購入履歴を見るのに画面を往復する | 1 画面にまとめる（タブ切替） |
| 商品状態が写真だけでは分からない | 複数写真 + 状態バッジ。**実装済み**（ImageGallery） |
| 検索してもノイズが多い | タグ・カテゴリ・状態での絞り込み。**実装済み** |

### 判断基準（この人が何を優先するか）

1. **手間の少なさ** > 売値の最大化。「あと 500 円高く売る」より「今日出品を終える」
2. **状態の正確さ** > 見栄え。盛った写真より、傷が写っている写真を信用する
3. **取引の安全** > 速さ。発送前に入金が確定していることを確認したい

## 2. 副ペルソナ — 田中 かずお（購入専従・慎重型）

購入しかしない層。**出品導線を邪魔しないこと**を確かめるために置く。

| 項目 | 内容 |
| ---- | ---- |
| 属性 | 40 代 / 専門職 / 特定ジャンル（カメラ・楽器）に詳しい |
| 利用歴 | 購入のみ 3 年。出品は「面倒そう」で試したことがない |
| 判断 | スペック・状態の記述を熟読する。写真の枚数が少ないと買わない |

### 設計への帰結

- **出品導線が購入体験を圧迫してはいけない。** 出品ボタンが購入フローの
  邪魔にならない位置にあること
- **商品説明・写真枚数・タグは、この人のために厚くする**（主ペルソナが
  書くのを面倒がる情報を、この人が求める）
- この非対称が C2C の本質的な緊張。**出品者は書きたくない、購入者は読みたい**

## 3. 意図的に外したペルソナ

**書かないと「考慮したつもり」になる。**

| 外したもの | 理由 |
| ---------- | ---- |
| 大量出品の事業者 | BtoC に近い。在庫管理・一括操作が要り、C2C の設計と衝突する |
| 未成年 | 決済・本人確認の要件が別物。モックの範囲を超える |
| 海外購入者 | 多通貨・言語・配送が要る。暗号資産決済とは別の課題 |

## 4. AI に使わせるとき

新しい画面を作るとき、**この文書を読んでから `screen-spec.json` を書く**。

判断の順序:

1. **誰の、どの役割の画面か**（佐藤の購入 / 佐藤の出品 / 田中の購入）
2. その人が**その場面で何に困っているか**（§1・§2 の表）
3. 困りごとを解くのに**どの部品が要るか**（kaze MCP で `get_component`）
4. 部品が無ければ**無いことを確認してから**作る（`search` で確認 → 記録）

**ペルソナに書かれていない困りごとを解く画面を作らない。**
作りたくなったら、まずここに追記して、なぜ必要かを書く。
